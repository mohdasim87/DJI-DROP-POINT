# DropPoint on the DJI Matrice 400

**Status: unverified — requires hardware.** Built and tested in simulation and
on an ARM64 Linux machine with no aircraft attached. Nothing below has flown.

Config profile: `config/profiles/m400/` · Packages: a `.dpk` you build for
Manifold 3, or `droppoint-m400_<version>_arm64.deb` for a generic companion
computer.

## Two ways to run it

| | A. DJI Manifold 3 (recommended) | B. Generic companion computer |
|---|---|---|
| Connects to | E-Port V2 port E1, E2 or E3 (DJI recommends E3) | E-Port V2 Development Kit USB port, through a USB-serial adapter |
| Laser rangefinder for target height | Yes | No — terrain tiles and take-off tie only |
| RC sound and vibration for the countdown | Yes | No — text only |
| Trigger a CZI TH4 from software | Yes (Widget Manager) | Yes in principle (Widget Manager is listed for Matrice 400 on Linux) |
| Own servo latch on a PWM pin | No — Manifold 3 has no PWM pins | Yes |
| Install | `.dpk` through DJI Pilot 2 | `.deb` with `dpkg -i` |
| Shipped profile setting | `psdk_platform: manifold3`, `advanced_features: true` | set `psdk_platform: generic_linux`, `advanced_features: false`, `psdk_link_mode: only_uart` |

The difference comes from DJI's Open Capability List: camera management,
gimbal management and liveview overlays are "advanced" functions, open on the
Matrice 400 only to a Manifold 3 or to developers DJI has granted advanced
permission.

## Weight

Maximum payload 6 kg (DJI measures this at the third gimbal connector at sea
level; it falls with altitude).

| Item | Weight |
|---|---|
| Zenmuse H30T | 920 g |
| Manifold 3 | 120 g |
| CZI TH4 V3 | 320 g |
| Mounts and cabling (estimate) | ~190 g |
| **Fixed equipment** | **~1.55 kg** |
| **Left for the payload** | **~4.45 kg** |

The profile ships `onboard_equipment_kg: 1.55` and payload profiles up to
3.2 kg. DropPoint refuses to start if a payload profile would exceed the
margin. Weigh your build and edit `aircraft.yaml`.

## Hardware

| Item | Notes |
|---|---|
| Zenmuse H30 or H30T | Camera, gimbal and the laser rangefinder (3–3000 m) |
| DJI Manifold 3 | Option A. Powered from the E-Port V2 port (14 V) |
| E-Port V2 Development Kit + USB-serial adapter (FT232 or CP2102) | Option B. The E-Port V2 has no UART pins; all links are USB |
| CZI TH4 V2 or V3 | Four hooks, SkyPort mount; CZI lists Matrice 400 support after a firmware update |

The Matrice 400 has four E-Port V2 ports at 120 W each, and port E4 can be
expanded through a hub, so the camera, the Manifold 3 and the drop kit can
all be fitted together.

For option B set `uart_usb_vid` / `uart_usb_pid` in `aircraft.yaml` to match
the adapter (FT232 `0x0403:0x6001`, CP2102 `0x10C4:0xEA60`).

## Drop mechanism options

| `release.backend` | Mechanism | AUTO release |
|---|---|---|
| `external_operator` (shipped default) | CZI TH4: operator presses the kit's widget in Pilot 2, or an RC button mapped to it | No |
| `psdk_widget` | CZI TH4: DropPoint presses the kit's widget through DJI's Widget Manager | Yes |
| `pwm_servo` | Own servo latch (option B only) | Yes |

Start with `external_operator`. To move to `psdk_widget`, run
`droppoint --probe-widgets <mount position>` with the kit fitted to find its
drop widget, then bench test with empty hooks. Full steps in
`docs/CZI-DROP-KITS.md`.

## Install — option A, Manifold 3

DJI installs Manifold 3 applications as a `.dpk` through Pilot 2, and the
installer checks the application's DJI app ID. The package therefore has to
contain your DJI credentials, so you build it yourself and never publish it:

```
scripts/package_dpk.sh m400 <build dir> /path/to/credentials.yaml dist/
```

This needs a Linux machine with `python3` and `dpkg-deb`. Install the
resulting `DropPoint-M400_v<version>.dpk` on the Manifold 3 from Pilot 2's
application management page and start it there. Logs are under the
application's `data/logs` directory on the Manifold 3.

## Install — option B, generic companion computer

```
sudo dpkg -i droppoint-m400_<version>_arm64.deb
sudo nano /etc/droppoint/credentials.yaml
sudo nano /opt/droppoint/config/aircraft.yaml   # platform, link mode, uart_device, release
droppoint --selftest --no-link --config /opt/droppoint/config
sudo systemctl start droppoint
```

## Flying a drop

1. Power on with DropPoint connected; wait for the floating window in Pilot 2.
2. Take off, climb to the release height, **hover at least 5 seconds** for the
   wind estimate.
3. Crosshair on the landing spot, SET TARGET. With a Manifold 3 the laser
   ranges the target and the window shows `LRF`. Check range and bearing,
   CONFIRM.
4. ARM.
   - **Hover drop:** follow `MOVE 4m BRG 265` until `DROP OK`, then release.
   - **Run-in:** fly towards the target at more than 1 m/s; the countdown
     starts 5 seconds out. In AUTO (software-actuated backends only)
     DropPoint releases by itself if the run-in is inside the release
     corridor, and aborts if it is not.
5. With an operator-actuated kit, press the kit's drop control on `DROP`, then
   RELEASE in DropPoint to log it.

## To verify on the aircraft before relying on it

- That the application installs and starts from Pilot 2 on the Manifold 3.
- Camera mount position (`camera_mount_position`) for the H30T so the laser
  readings come from the right gimbal.
- Heading, pitch, roll and gimbal angle signs, as in the Matrice 4T guide.
- That the CZI TH4 responds to a Widget Manager press, and which widget index
  drops one hook.
- `cda_airframe` against a measured wind, and five measured drops per payload
  profile for `droppoint_calibrate`.
